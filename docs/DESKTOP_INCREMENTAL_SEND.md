# 桌面目录增量发送

主界面选择“增量发送目录”，扫描本机目录并通过已认证会话比较接收端相对路径。预览显示源目录、固定对端、新增/修改/未变化文件数、目录条目数，以及预计传输/节省字节。计算中和预览完成后均可取消；确认前不创建任务、不分配接收暂存文件、不备份或发布文件。

点击“确认发送”后，保留本次扫描的目录清单并进入现有公平发送队列。发送前重新验证源文件；预览后源内容变化会明确失败，不能把新的内容悄悄混入旧清单。接收端再次比较实际目标，目标由相同变为不同则正常传输并备份。后续新增的源目录条目需要重新选择。

内容一致必须满足完整 BLAKE3 清单、大小及持有文件句柄的身份/修改时间检查；不能只凭路径、大小、时间或旧历史记录跳过。比较通过后保留不跟随链接的根、父目录和文件句柄，在任务库唯一写入者中重验路径与身份、同步已有数据及目录，再提交专用跳过回执。相同文件保持原文件身份，不生成新备份或新的数据暂存。已有未完成暂存只在回执提交后清理，清理失败可随回执重放重试。

新增和修改文件继续使用既有分片校验、磁盘空间预算、checkpoint、备份和原子发布。这里按完整文件过滤，不提供文件内部的差分块传输。空文件仍需校验；空目录仍通过目录任务确认。接收端额外文件保留。普通“选择目录”、拖拽发送和 CLI 保持原传输语义。

完成任务的详情显示实际跳过数量和节省字节；目录详情聚合全部保留子任务。增量偏好与实际跳过结果随任务记录持久保存。旧记录缺省这两个字段为 false；普通任务不写入额外字段。新增量记录由支持本功能的版本管理。节省量为跳过的文件内容字节，不包含协议控制帧，也不是此前预览值的简单拷贝。

## 协议与资源边界

桌面新增可选能力 `CAP_INCREMENTAL_DIRECTORY`（bit 12），只在协商成功时发送追加的 CompareFile、ComparedFile、IncrementalOffer 消息，既有 postcard 枚举位置不变。增量文件使用完成回执版本 2 表示已验证现有内容；任务状态机要求对应的增量 Offer、正确身份、根哈希、方向和序号。普通 Offer 不接受版本 2。新端连接旧端时预览明确显示“不支持增量比较”，确认后采用原有全量 Offer 和版本 1 回执。

比较与文件发送均受方向密码/可信设备授权及实时撤销约束。远端只提交经验证的相对名称和有界清单，没有远端绝对路径或任意文件读取接口。原接收根、链接/reparse point、大小写/Unicode 别名及源路径限制继续生效。

预览请求和确认绑定本机请求 ID、NodeId、连接 stable ID、会话 epoch 及扫描记录。旧请求结果不能替换新的选择；取消、会话重建、连接更换和过期后必须重新预览。预览最多保留 8 个设备/目录；应用比较工作者最多 2 个，目录条目与总清单沿用既有扫描上限。扫描与比较总预算 5 分钟，准备就绪后的确认窗口 5 分钟；单文件内容比较预算 120 秒。源扫描支持取消，比较等待定期检查取消及总预算；阻塞文件读取在下一次读取边界检查预算。发送阶段的比较定期发送任务绑定保活，避免将正常哈希等待误判为网络中断。后台哈希、同步及回执提交持有尝试所有权，不能被新尝试抢占。

Windows 同步已有数据需要有写权限的句柄，但不会截断或改写内容；无法同步或无法可靠读取元数据时明确失败，保留已有文件。

## 验证边界

自动验证使用真实身份认证 QUIC 和生产 Session 命令，覆盖预览/取消/确认、新增/修改/相同内容、空文件/空目录、多余文件保留、原身份保留、备份、请求替代/数量上限/过期/会话及连接更换、预览后源或目标改变、跳过回执丢失重试、暂存清理、任务记录重读和实际节省量。另验证增量回执及保活需明确选择增量、路径穿越/链接/别名拒绝、比较期间路径替换和旧记录缺省。未授权文件命令回归包含预览和确认。

对应平台 CI 验证库回归、原生编译和打包；Mac/Windows 原生选择对话框、预览面板排版及取消交互仍需在相应桌面环境人工验收。自动回归通过不代表上述人工交互已验收。
