# 桌面断网自动恢复

设置页的「断网自动恢复」默认关闭。开启后，本次进程中已经开始的文件或目录任务，在 QUIC 超时、连接重置或验证过的候选地址变化后可以继续原 TaskID；不重新扫描选择、不改变已绑定对端、源路径或接收根。

恢复前等待旧执行器释放活动和发送槽，重新建立 QUIC/TLS、Ed25519 身份认证和方向授权。发送端优先入公平发送队列；接收端延迟请求继续，避免两端同时发起。仅接收端开启时，继续 RPC 同时要求出站和入站权限。当前进程里已有的密码仅保留于内存，可信设备仍通过现有认证交换重新验证，配置中不保存恢复意图或明文密码。

每个任务自首次断线开始最多等待 5 分钟、累计最多 5 次尝试（包括重连查询与继续请求），失败按 2/4/8/16/32 秒退避。已有连接查询和当前任务活动会去重；任务行显示等待重新连接/验证权限，并可点击暂停取消。关闭开关取消尚未重新开始协商的本机恢复；已开始传输的任务可用暂停停止。关闭本机开关不会撤销对端正常的已授权接收权限，因此对端可以为其本次运行中的中断任务发起恢复。

主动暂停、权限撤销、密码变更、网络设置重建、接收目录变更或退出应用，会取消相关恢复意图。源文件缺失/变化、存储错误、未知协议错误不会进入自动重试。进程或端点重启后仍需用户手动继续；自动请求不能恢复对端已暂停、重启恢复或存储失败的记录。匹配的已完成持久回执可以安全重发。

协议增加可选 `CAP_AUTO_RESUME` 能力和末尾追加的 `AutomaticOffer` / `AutomaticResumeTask` 消息；既有消息序号、格式和版本保持不变。只有协商该能力的新版本对端参与自动恢复，旧版本仍可手动继续。自动请求在接收 TaskStore writer 内再次检查绑定和状态，不以普通手动 ResumeTask 绕过对端暂停。

配置 schema 10 增加 `auto_resume`，旧配置迁移为关闭。独立偏好保存使用原子写入，旧设置草稿不会覆盖较新的偏好。

## 验证范围

真实双端 Session 测试覆盖发送端单独开启、接收端单独开启和双端开启；关闭真实 QUIC 连接后重新认证，断言新的 generation、连接和 TLS binding，同一任务最终字节一致且双方持久回执已提交，同时覆盖含空目录的目录传输和已有 durable bitmap 的断点恢复。测试通过仅测试可见的命令注入 Quinn 超时/重置证据，避免每个矩阵等待 UDP 空闲超时；传输、连接重建、身份/密码授权、排队和文件发布使用真实实现。

额外真实 QUIC 测试覆盖接收端暂停/重启、发送端暂停、入队前/后关闭开关、权限撤销、源文件变化/缺失和接收发布失败；策略测试覆盖退避、尝试/时间/容量限制、方向权限和去重。原有重启恢复、目录、持久检查点、完成回执及限速回归继续执行。CI 与本地自动测试不代表原生 macOS/Windows/Wayland GUI 或真实双 NAT 验收。
