# 桌面接收磁盘空间预检查

接收文件与目录之前，在后台查询实际文件系统的可用空间。同一文件系统的并发任务共享预约预算；安全余量默认 64 MiB，可在设置中保存为 0..4096 MiB，修改只影响后续预约。1 MiB = 1024 × 1024 字节。

文件需求为文件长度减去重新读取、哈希校验通过的持久位图分片，再加每个任务 64 KiB 的元数据估算。未 checkpoint 的进度、损坏分片或长度不符的临时文件不计作已完成。预约成功前不创建、截断或调整数据文件，也不修复持久位图。已存在但需要重写的分片可能使计算更保守。目录任务预约元数据估算；每个文件系统的安全余量只算一次。

Unix 使用已打开目录上的 fstatvfs 和文件系统设备号。Windows 使用已打开目录的卷 GUID / 卷序列号及 GetDiskFreeSpaceExW 的调用者可用字节，保留 64 位数值并考虑配额；网络共享不支持卷 GUID 时使用卷序列号归并，序列号冲突会保守地共享预算。查询通过现有不跟随链接的目录能力完成，远端路径不会成为新的环境路径权限。暂存文件和目标父目录跨文件系统时提前拒绝，保持原子发布边界。

实际写入成功后减少未来待写预约，元数据估算保留到结束；其他任务入场时重新查询可用空间。查询期间出现预约、进度或释放变更会重新读取，最多重试 4 次。最多 64 个同时预约。预约随实际后台 IO 持有，即使网络任务被取消，也会等已有后台写入结束才释放活动和预算。完成、暂停、断线、失败及退出不会遗留内存预约，不删除用户文件或主动清理未完成断点。

空间不足、无法查询、预算忙和跨文件系统分别显示安全诊断，保留任务供手动继续；实际 IO 返回 ENOSPC / StorageFull 也显示磁盘空间不足。预检查是提前发现问题的估算，其他进程、配额和文件系统仍可在传输过程中改变空间。设置页面显示当前总预约量和文件系统数量，无同步文件系统查询。

配置 schema 11 将旧配置迁移为 64 MiB，拒绝旧版本声明其他余量，窄范围原子保存不会被旧基础设置草稿覆盖。CLI 的 PartialDownload 仍使用原接口；新增入场回调只用于桌面接收。

自动验证包括同盘并发与不同实际文件系统、预约生命周期和后台 IO 持有、溢出/查询失败/容量/变更重试、持久断点重新校验和拒绝时不改写、真实 QUIC 的文件/目录不足与手动重试、完成/暂停/断線释放，以及 Linux /dev/full 获取真实 ENOSPC 后经既有发布测试入口验证接收诊断、保留断点与重试。该 ENOSPC 夹具不填满用户文件系统。四平台构建/完整回归与真实 GUI 交互、真实满盘验收分开记录。

原生 API 参考：[GetDiskFreeSpaceExW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdiskfreespaceexw)、[GetFinalPathNameByHandleW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew)。
