# 桌面系统通知（Issue #66）

设置页的「系统通知」默认关闭，开启后保存到当前用户配置，并检查系统通知服务/权限。
旧 schema v1–v7 升级至 v8，通知仍关闭。关闭停止新的投递和点击路由；再次开启不会
补弹已清除的待发结果。单独保存通知偏好不会被旧的高级设置草稿覆盖。

软件启动时的第一次任务快照只建立基线：历史完成、失败和重启恢复的中断记录不通知。
随后观察本次运行的完成、失败或中断状态变化。连续进度或重复快照不重复提醒；
失败任务重新进入运行后可以报告新的结果。目录只在整体完成或首次出现失败/中断时
提醒，部分文件成功不逐条弹出。两秒内的多项结果合并为一条，失败任务优先定位。

通知标题和正文只包含软件名称、结果种类及数量，不发送文件名、完整本地路径、
设备 ID、密码、令牌或原始错误。目录数量与列表一致，包括目录元数据任务。

点击当前通知的正文或「查看任务」时，通过有界内部事件队列恢复同一个主窗口、
关闭设置页、展开对应目录并滚动选中任务。记录已清理时显示提示。停用通知后的
旧回调会被偏好世代隔离；通知不会启动第二个软件或网络 Session，也不执行传输操作。

原生后端使用锁定版本 notify-rust 4.18.1：Linux XDG D-Bus、Windows Toast、
macOS UNUserNotificationCenter（preview-macos-un，mac-usernotifications 0.3.1）。
macOS 必须运行有真实 bundle ID 的 .app；裸开发二进制不能申请通知权限，
检查失败时降级为设置提示。开启时请求系统授权；系统拒绝/免打扰可能阻止显示。
Windows 使用软件自己的 AppUserModelID 和当前用户 DisplayName 注册，不借用 PowerShell
身份，也不需要管理员权限。Linux 通知服务不可用时保持传输可用。

系统通知的显示、保存和按钮由操作系统/桌面环境控制。回调支持当前进程中尚未关闭的
提醒；关闭/移入系统历史后的点击支持依原生后端而定，退出软件后的通知不自动启动软件。
通知请求/事件队列及响应等待线程均有上限，不阻塞 GUI、传输或退出；服务调用失败、
权限拒绝和资源忙均在设置页提示，不把原始系统错误写到通知。

现代 macOS 后端要求 Rust 1.90，因此 Cargo 最低版本声明和四个打包 doctor 同步提高到
rustc/Cargo >=1.90.0；过旧或无法解析的版本在 Cargo 构建前被拒绝。

验证：历史去重、重复快照、重试、目录/短批次聚合、隐私字段、关闭与点击世代隔离、
配置迁移和旧草稿保存由自动测试覆盖。Linux 额外在全新的隔离 D-Bus 会话中模拟通知
服务，调用真实原生后端并发出 default activation，检查数量正文和任务 ID 路由。
该 fixture 单独执行，普通完整库测试中有说明地忽略，不发送真实用户通知：

```sh
dbus-run-session -- /usr/bin/python3 scripts/desktop-notifications-smoke.py \
  --output /tmp/p2p-notifications-new.json
```

四个平台原生编译验证 API 可用性；真实 macOS 权限面板、Windows Toast 与桌面环境
按钮/免打扰行为仍需相应平台人工验收。
