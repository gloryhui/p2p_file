# 桌面拖拽文件与目录发送

在主窗口拖入本机文件或目录，可一次提交混合批次。拖入时固定到当前已连接且获准出站文件访问的设备；编辑设备 ID 不会改写已提交任务的目标。只有原生 ExternalPaths 才被接收，普通文本和网址不作为文件路径提交。

设置页面、设置编辑、诊断面板、文件选择/删除确认对话框、清理历史、导出诊断或保存设置期间禁用拖入；测速进行中或待响应期间也禁用。未连接/未授权或任务存储不可用时不能提交。可拖入时主界面显示提示，悬停显示底色反馈。每次最多 128 项，单个路径最多 32 KiB、整个批次路径最多 1 MiB；限额和绝对 UTF-8 路径检查是内存操作，在克隆和排队前执行，不查询文件系统。

后台先检查整个批次的顶层项是否仍存在、为普通文件或目录，拒绝符号链接、Windows reparse point、非普通文件、相对路径和父目录跳转。完全相同的规范组件路径去重；同时选了目录及其内部子路径时，仅扫描父目录一次。去重不执行 canonicalize，不因为解析链接扩大源权限；路径别名和大小写仍由现有源扫描与可移植目标名检查处理。

通过顶层检查后依次复用文件选择、目录扫描、TaskStore 入场、公平发送队列及持久回执入口。目录内链接、名字冲突、源变化和扫描限制保持既有策略。顶层预检查失败时本批次不创建任务；若之后某项扫描失败，前面已经加入的任务保留并继续出现在列表，界面明确提示未全部加入及已加入数量，其余项需要重新提交。本批次不是整体回滚事务。

一个有界 Session 命令携带整个批次，仍要求当前 generation 的出站文件授权，并受选择工作池与测速互斥限制。权限撤销或旧会话退出会取消正在进行的扫描；同批次剩余项不会在重建的会话中重新入场，不自动更换设备或密码。已有任务按原暂停、中断和手动恢复边界处理，不扩展网络协议或配置格式。

自动验证覆盖纯 UI 接收条件、路径数量/大小/编码边界、重复与目录重叠、缺失/链接拒绝、扫描失败保留已入场项、入场后会话 epoch 改变，以及真实双端 Session 的混合批次、空目录、字节及回执。原密码方向授权测试也覆盖未授权批次命令。原生四平台编译与完整回归可以验证接入路径，真实 Finder/Explorer/X11/Wayland 拖入和对话框交互仍需在相应桌面环境验收，不能从 backend 测试推断已经完成交互验收。
