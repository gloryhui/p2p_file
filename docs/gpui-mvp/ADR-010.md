# ADR-010：进程级恢复与故障矩阵

状态：T011 实施决策；验收文档固定在 `2041a38756b87ba7856dcd343624d98df2283c5a`。T012 的打包、物理设备、双 NAT 与 600 秒门禁保持有效。

## 测试所有权与证据

`desktop::e2e` 整个模块仅在 cfg(test) 中编译。父测试启动当前 libtest 二进制的精确 actor 入口，使用有序、有期限的 stdin/stdout 请求调用生产 DesktopSession 命令，并查询 T010 同一轻量 UI 投影。actor 没有替代网络路径；真实信令服务器、UDP 打洞、QUIC、Ed25519/channel binding/目标身份、桌面能力、TaskStore、队列、收发、发布与回执均走生产实现。没有 GUI RPC 端口、隐藏生产环境开关、第二个接收循环或 test-only 产品按钮。

每个测试独立临时端口、身份、私有根和数据，父进程拥有并回收子进程/日志读取线程/信令线程。响应和状态等待有截止时间；失败保留私有 fixture 便于调查，不把私钥写到证明日志。无 env 标记时 actor 入口作为普通测试立即返回，不使用 ignored 测试。脚本不覆盖旧证据，也不在 checkout 内写结果；matrix 记录平台、命令、当前 SHA 与 dirty 标记，不能将未提交快照称为 exact-head。

真实硬杀调用 OS Child::kill；Unix 同时断言退出信号为 SIGKILL，Windows 是 TerminateProcess。杀死发送端/接收端后重开真实 Session，身份、TaskID、接收根保持，恢复记录不自动排队；用户明确连接/Continue 后核对完整 70 MiB 内容、哈希和双方持久回执。发布另在十个 journal/文件系统/回执边界驻留真实子进程，硬杀使析构函数不执行；重开恢复、旧内容唯一备份、新内容和回执均核验。原 T006 进程恢复与 T007 注入测试保留。

磁盘满用测试编译的 publication I/O ErrorKind::StorageFull 注入；PermissionDenied 注入同样明确标模拟。错误经过真实接收与 finish_error 到 UI 投影，失败/安全诊断/零速率/可重试和保留旧内容均检查，恢复后仍使用同 TaskID。另有 Unix 真实 chmod 0500 接收目录拒绝，测试须以普通用户运行；Windows 保留真实被占用目标测试。没有为模拟 StorageFull 填写“真实磁盘已满”。

## 故障发现：端点重启仍被视为重复连接

新的 Session 硬杀 harness 暴露：存活端旧 QUIC 连接未到 idle timeout 时仍是 Connected，显式 Connect 被忽略；重启端的新 socket 无法与旧 generation 完成打洞。这是实际失败，不通过加大 timeout、删除断言或全局串行化规避。

显式 Connect 在已连接状态刷新信令候选。每个开始的 generation 保存有界、去重、排序的候选集合，Relay 不参与；相同集合保留认证连接。已注册同一 peer 的候选映射改变且仍有可用地址时，只关闭该 peer 旧 generation，重新执行 Punch/QUIC/身份/能力验证。旧 close/failure 回调仍按 generation 拒绝；不自动恢复任务，也不改变 QUIC 参数。注册/候选不是认证成功，不能提前显示 Connected。候选集合在当前失败/断开/重配置清理，容量受既有 peer/candidate 上限约束。

新增“映射未变”回归等待实际候选已处理的通知，再核对两端 connection stable ID 并传真实 UNI 数据；不是只验证 Connect 命令入队。信令暂时断开仍保留现有 P2P 连接，原回归保持。
