# ADR-007：全局发送队列、字节公平与有界进度

状态：T008 实施决策。固定验收文档 ref 为 `2041a38756b87ba7856dcd343624d98df2283c5a`；本 ADR 不改写验收标准。T010 消费本任务的任务/分组/事件/速率呈现接口。

## 入队、资源与生命周期

扫描完成后，在同一 TaskStore writer 临界区持久化稳定 TaskId/peer/源路径/目录组及 Queued，并提交内存队列 admission；读者和暂停不能看到 Queued 尚未入队的间隙。首次文件/目录选择直接完成 admission，Session 不再二次调用 Continue/入队，避免在选择返回前暂停后被再次激活。队列 mutex 只用于短暂校验/入队，不跨扫描或大批磁盘快照写入。任务按入队顺序进入当前会话的 FIFO，最多 4096 个等待条目。默认活动发送文件数 1，配置仅允许 1、2、3；保存设置成功后应用。3 降为 1 保留已经活动的任务，直到活动数低于新上限才补位。离线 peer 的等待条目保留原顺序，调度跳过它们，为已有认证连接的任务分配槽；不能重绑定任务或自动改用其他 peer。

目录中的子文件各用一个文件槽。目录条目是实际元数据控制任务，单独上限为发送/接收各 8、每 peer 各 2，不占数据文件槽。接收文件单独限制全局 3、每 peer 3；它不被本机发送数挤占。接收满额在创建接收任务/打开暂存文件之前回明确 Busy，发送任务保留稳定 ID，标记可手动重试的 PeerBusy。对端 ID-only Continue 仍须匹配已有授权源任务，使用相同发送预算；不会绕过上限或新建接收路径。

每个预留槽有单调代数及 RAII 所有者，执行器尚未 poll 时的取消同样释放槽。迟到的旧执行器不能释放新尝试的槽。排队/预留未启动任务的暂停与任务库写锁及 admission 同步，取消其 nonce 并持久化 Paused；实际活动任务沿用 T006 的双方 checkpoint/暂停确认，不丢分片，最后 Completed 可以赢过 Pause。完成、错误、暂停、执行器取消都释放槽。用户在 Paused/Interrupted 可见而旧执行器尚未完成 RAII 清理时点 Continue，会在 writer 锁外等待旧活动和旧槽释放，再执行新 admission；不把这个明确继续请求误当成活动任务的重复请求而丢掉。恢复的 Interrupted/Paused 不会自动加入当前运行队列，必须用户 Continue；新会话 epoch 拒绝旧 admission 和旧写入。

Session 现有 peer_tasks JoinSet 直接拥有选择工作和所有队列执行器，认证连接表仍由 Session 唯一拥有。停止会话先取消并 drain 所有任务，再持久中断，不额外引入脱离会话的队列运行线程。选择命令最多 64 个排队、最多 3 个扫描 worker；扫描不占发送槽。单文件/目录哈希均在 cancellable blocking worker 上完成，不持有任务库 writer 锁。进入首次持久提交前再次检查取消 token 与扫描开始时捕获的 session epoch；丢弃一个还在等待 blocking worker 的选择 future 不会遗留幽灵任务。持久提交开始后任务由稳定 ID 的暂停/继续生命周期管理。网络等待不持有全局 admission/公平锁。

## 实际字节公平

所有发送文件共享一个按就绪任务轮转的调度器，最多登记三个数据 writer。每 TaskId 持有贯穿整个尝试的 WriteTicket，每份 quantum 为 64 KiB。`poll_write` 使用实际接受的 payload 字节扣减 credit；短写继续花完当前份额，花完后轮转。首批参加调度的流先取得首份额，避免首个整份短写的流独占第二个 quantum；同步成功写也显式 yield，让其他文件 future 能登记就绪。后续新任务正常加入环尾，连续小任务不能反复抢占首份额、饿死既有就绪任务。Frame 长度/协议前缀和小控制帧不计入文件数据份额。分片的序列与门禁仍由既有 TaskProtocol 验证，postcard Chunk.data 必须是最后字段并验证编码后缀。

底层写 Pending 或没有已准备数据时退出就绪环，其他任务立即借用份额；该任务由自己的 I/O waker 或下一次准备数据重新进入环。未用 credit 最多一个 quantum，没有累积无限信用。公平 mutex 在调用实际 AsyncWrite 之前释放；写错误/取消/模拟底层 panic 后其他任务仍可调度。三个 spawn 只是并发，不作为公平证明。

对于同一观察起点、持续有数据且持续写就绪的 N=1/2/3 任务，任一两个任务累计实际写入 payload 的差不超过一个 quantum（64 KiB）。模拟 AsyncWrite 使用 137、4093、65536 字节短写的三组顺序（包括全部 65536 和首项 65536），在 20000 轮的每一次 poll 后断言该边界并验证每个任务获得多份额，另验证真实异步循环面对永远 Ready 的写模型仍每次写入差 ≤一个 quantum、poll 时全局锁未持有，以及慢写借用/重新就绪没有信用突发。真实网络接收量还受每任务 WINDOW=4、最大 1 MiB chunk 的在途数据影响，不能把应用写入公平称为任意瞬间接收带宽等分。QUIC window 和文件 WINDOW 未调优。

## 缓存与呈现

解码帧前读取长度并校验 4 MiB 上限，随后取得按 64 KiB 单位计数的内存预算，再分配。按原始帧和解码 payload 可以同时存在计入两倍长度。解码帧持有 lease，跨有界 channel 和实际处理期间保留预算；EOF、非法帧、取消、处理结束自动释放。单任务帧预算 8 MiB，channel 容量 2；所有读取帧共享 64 MiB，其中大帧最多 56 MiB，为小控制帧保留 8 MiB。首帧也使用同一全局预算及 5 秒期限，Offer 的 lease 到持久绑定完成即释放，不贯穿整个文件传输。

这些是应用帧缓存预算，不是整个进程 RSS 或 Quinn 内部缓冲的承诺。发送最多 3 个文件，每个最多一个待发送 1 MiB chunk，编码时短暂共存两份 payload（合计最多 6 MiB），Offer 编码另受既有 4 MiB 帧上限和活动槽数限制。目录控制条目没有文件 payload。TaskStore/清单、协议状态、bitmap、UI 与传输层仍遵循其各自已有条目/清单/窗口上限；测试不伪造 RSS 门槛。

累计进度只来自验证的恢复 bitmap、分片确认/接收验证与持久 Completed。短窗口速率使用单调时钟，恢复的旧字节先设为 baseline，不算新增网络流量；非 Transferring、暂停或两秒无采样显示零，观察点最多 32。分组统计所有子条目及已确认字节，只有每个子项 Completed 才 Complete；Failed/Interrupted 单独汇总为部分失败。

事件 FIFO 最多 256。相同任务的 ProgressHint 合并；进度不能挤出生命周期事件。任意多个生命周期/终态无法塞进固定 FIFO 时置 resync_required，呈现 API 原子读取当前任务快照、事件及该标志。终态的可靠来源是持久 TaskStore，消费者必须以随附快照重建，不能把丢失 delta 当成终态丢失。读取快照不产生新进度事件或自行唤醒循环。

## 验证与发布边界

本地公平测试使用注入时钟/实际模拟写就绪，不设公网 Mbps 门槛。真实认证 QUIC 测试覆盖同 peer 的 1/2/3 槽、预启动暂停/旧 nonce、独立接收 Busy 后 Continue、被 disk gate 阻塞任务旁边的独立文件完成、暂停后待发任务补位、目录部分失败和事件 overflow 快照恢复。T006 真实杀进程/恢复、T007 目录发布与全部原回归保持启用。

按 owner 成本规则，开发阶段只跑本地检查；最终候选仅需一套 GPUI 三平台及 windows-all 成功结果。工作流显式 checkout PR head，测试/Clippy 使用矩阵 native target，复用同 target 的 GUI 编译；三平台和所有验收作业保留。此工作不能证明物理 Windows/macOS UI、双 NAT 或 T012 原生 600 秒测速验收。
