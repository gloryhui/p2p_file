# ADR-008：认证连接上的内存测速与取消确认

状态：T009 实施决策；固定验收 ref `2041a38756b87ba7856dcd343624d98df2283c5a`，不改写验收标准。T010 消费 Session 测速命令和安全领域快照。

## 归属、能力与资源

测速复用已经完成 QUIC、Ed25519、channel binding 和目标 NodeId 确认的连接，不新建业务连接。既有 TransferService 是唯一 accept_bi owner，按首帧分发文件、ID-only Continue 或 Speed；每个认证连接另有且只有一个 accept_uni owner。Session 的既有 JoinSet 拥有命令/连接业务任务；连接业务 JoinSet 拥有单向流 header worker，结束时 abort 并 drain。没有新的全局可变 runtime 或独立 UDP reader。

较小 NodeId 是唯一 lease 协调者。较高节点向它发送 Request；较低节点的本地请求也由同一个 SpeedArbiter 分配 lease。首个被协调者接受的请求得到一个 lease，其余得到 Busy，不承诺某个 UI 固定赢。双方收到 grant 后先原子取得文件/测速门禁，交换 Ready，才打开数据流。grant 绑定 test_id、owner、direction、seconds、随机 128-bit stream_token；单向流首帧必须完全匹配当前 lease 和实际认证发送方，且只能 claim 一次。

新增 CAP_SPEED_EXECUTION=64，Hello 当前能力为 127。此前 CAP_SPEED_OWNERSHIP=8 只提供 schema，不能据此认为旧客户端会执行测速。旧 Hello 15/31/63 明确无法完成新业务协商；黄金测试仍保留旧 Hello 字节及所有原 CLI 消息编号。SpeedControl 只在 enum 尾部追加 Ready/Result，CLI ControlMessage 与默认语义不变。

每 peer 的 Activity 锁同时保护扫描选择、发送预留、接收活动和测速 lease 的原子准入；RAII permit 覆盖清理期。测速开始遇到活动文件（包括目录元数据和扫描）返回明确 Busy；测速期间新文件选择/接收拒绝，已经排队但尚未活动的稳定任务继续保持 Queued，调度跳过该连接，lease 释放后正常补位。不静默暂停或改变任务绑定。其他 peer 的活动独立，测速结果不承诺排除其他连接对物理链路的影响。每连接本地最多一个进行中的请求，首帧/握手等待有期限。完成/取消已进入清理阶段时，新请求在锁外等待旧 lease 释放；不把这段清理误报成运行中 Busy，也不等待仍在运行的测速。

## 数据、计时与取消

共用 src/speedtest.rs 的 memory-only send/receive kernels。调用方传入已经确认归属的 stream，kernel 不做 accept，不涉及 File/manifest/chunk/bitmap/接收目录。固定 64 KiB GUI buffer，实际短写逐次计数；单调 Tokio 时钟控制数据期限，阻塞写受 deadline 与 idle 双重限制。CLI 仍默认 10 秒，上限有针对性扩展为 600 秒，wire 参数和解析器一起验证 1–600；GUI 协议仅允许 30 或 60/120/.../600。

两端交换各自实际 bytes 和 elapsed，核对 bytes 相等、正数耗时及期限，再交换匹配的 Finished。两个 UI 的最终 elapsed 都选择实际数据接收方 observation（毫秒表示），不能改成发送端 write/finish 耗时。快照提供 bytes、elapsed、平均 bytes/s、RTT、方向/归属/时长/状态。运行采样最多约每秒一次，终态单独更新；取消/中断速率为零。T010 可从原始 bytes/elapsed 计算 MiB/s 与十进制 Mbps，不把两者混用。

取消先发送绑定 lease 的 Cancel，等待匹配的 Finished 取消确认，并完成控制流关闭确认，再释放 owned 数据 future/流和 lease。取消确认期间数据 future 保留且不再 poll。若先 reset 单向流，QUIC 跨流到达顺序可能使对端先看到数据错误而看不到 Cancel；本地严格取消状态回归曾失败，修复后保留断言验证。双方同时取消也能互相确认。已校验结果并进入 Finished 的完成边界允许完成赢过迟到取消。

控制读取有独立有界 reader/channel，select 不反复丢弃半帧读取。运行阶段控制等待和总体期限按本次 duration+idle 计算，没有 300 秒固定上限。所有取消/错误只 reset/stop 本次拥有的流，不能关闭共享连接；旧 token 的单向流由唯一 dispatcher 停止，不能交给新 lease。单向首帧先检查 4096 字节上限，最多 8 个 header worker、每个 5 秒；非法或重复来源 stop=5，不推进当前测试。BI 首帧仍受 T008 FrameBudget 和业务 handler 上限保护；其后的测速控制帧使用独立 4096 字节上限及容量 4 的 channel，不把这部分小控制缓存冒充 FrameBudget lease。

## 证据边界

可控时钟实际运行共享发送 kernel，通过 300/599 秒不提前结束、600 秒结束及短写精确计数；CLI 接受 301/599/600，拒绝 601，保留默认 10 秒和旧消息字节。真实认证 Linux loopback 集成用 cfg(test) 时长缩放验证两个方向、同一接收方结果、双方同时请求的一胜一 Busy、文件互斥、双方发起取消、旧 token、错误 token/超长 header 明确 stop，以及取消后的新测速和真实文件回执。错误 token 的测试在合法数据发送之前用 gate 注入并检查 stop，而非依赖数据流已经 claim 后的重复拒绝。

完成后立即再次开始还使用 cleanup/wait 两个确定性 gate：旧 lease 保留到清理结束，新请求确实等到释放后取得新 test_id。去除接收侧清理等待曾使保留的严格测试复现立即 Busy，失败日志保留。

这些是可控时间/loopback 软件证据，不是物理双 NAT、最低 Windows 系统、Apple Silicon 交互或原生 600 秒证据。后者仍由 T012 实际环境验收；没有固定公网 Mbps 成功门槛。最终 exact-head CI/Review 记录于 Issue #24，不把旧 head 的 CI 用于新候选。
