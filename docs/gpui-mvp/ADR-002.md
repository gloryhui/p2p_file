# ADR-002：T003 本地任务存储与启动恢复

状态：T003 实施决策，待控制层复核

## 决策

T003 使用本机 JSON 原子快照，文件位于应用 data 目录的 `tasks.json`。当前任务模型体量较小，也没有需要引入数据库事务、并发读写或查询引擎的 UI；复用已有 serde_json，不新增 Cargo 依赖。快照以稳定 TaskId 排序，便于诊断和测试。超过 16 MiB 的文件拒绝读取，不尝试截断或重写。

格式包含顶层 `format_version`、单调递增的 `generation` 和任务记录数组。顶层格式版本为 1；每条 TaskRecord 也保存独立 `schema_version`。未知顶层版本会报告 unsupported version；格式损坏、截断、未知字段、重复 TaskId 或无效记录会报告诊断错误。遇到任何拒绝条件时保留原文件，不自动格式化、迁移或替换它。T003 不提供自动迁移；未来格式变更必须增加兼容性测试并明确迁移决策。

## 记录边界

任务绑定包含随机生成的 128 位小写十六进制 TaskId、现有 NodeId 的规范化表示、发送/接收方向、本机 source 或 receive root、BLAKE3 manifest 身份、文件字节数与分块参数、生命周期状态、时间戳和受限诊断代码。源路径/接收根是用户授权的本机恢复绑定，会保存在仅本机任务快照中；不保存对端绝对路径、密钥、内容字节、任意错误文本或传输 bitmap。

TaskId、peer、方向、本机路径和 manifest 是不可变绑定。状态只可通过生命周期表变化。sender/receiver 恢复查询只接收 TaskId，并返回已经持久化的本机绑定；调用者必须另行进行显式用户操作。查询不会自动排队或恢复传输。

启动时将 Scanning、Queued、Connecting、Negotiating、Transferring、Pausing、Finalizing 改为 Interrupted 并提交；Paused、Completed、Failed、Interrupted 保持原状态。恢复快照成功持久化前，TaskStore 不返回给调用者。Paused 不自动继续；Interrupted 也等待用户明确选择。任务 DB 的 ProgressHint 只是显示提示，不是 receiver bitmap/checkpoint 的权威来源。内存进度可以频繁更新，但只在调用显式 coalesced flush 时写入快照，不按 chunk fsync。

## 单写者与提交边界

桌面启动先持有现有 per-data-directory `instance.lock`，其生命周期覆盖 TaskStore。TaskStore 还持有同目录的 `tasks.lock`，让第二个直接打开同一快照的写者也会被拒绝。TaskStore 的所有修改要求独占 `&mut`，不会提供并发写入口。创建、转换状态和显式快照写入都先构造候选集合，校验 TaskId 唯一性及模型不变量，提交成功后才将候选集合发布到内存 API。

每次提交在目标文件同目录中用随机名称和 `create_new` 创建唯一临时文件；Unix 权限为 0600。Windows 临时文件、任务文件和锁文件继承应用 data 目录的安全描述符，本任务不自定义 Windows DACL。写完整个序列化快照后对临时文件 `sync_all`，然后替换现有快照。临时文件由清理 guard 负责删除；替换成功后清理路径不再指向该文件。

- Unix 使用同目录 `rename` 原子替换，之后对父目录 `sync_all`，使目录项更新进入文件系统提交边界。
- Windows 使用同目录 `MoveFileExW`，设置 `MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH`，不启用跨卷 copy。GPUI/CI 会编译和执行目标平台测试；本 worker 的 Linux 执行不能被表述为原生 Windows 运行证明。
- 如果替换前失败，旧快照保持不变，候选状态不会发布到内存。如果 Unix 替换后父目录同步失败，替换可能已可见而掉电耐久性不确定；当前 TaskStore 会拒绝后续写入并要求重新启动读取实际快照。
- `sync_all`、同目录原子替换和 Windows write-through 提供上述操作边界，不承诺硬件、驱动或网络文件系统一定遵守掉电持久性语义。该目录必须是本机应用私有数据目录。

## 恢复与错误策略

活动任务启动恢复为 Interrupted，不自动恢复连接、文件读取或传输。Pausing 等状态也一律中断，避免假设上次进程在安全检查点退出。Paused 保持 Paused。已完成和失败记录不会因重启被重置。

截断 JSON、未来版本、权限不满足、非普通文件、符号链接和无效记录都会明确拒绝；拒绝时不写原路径。临时文件写入或原子替换前故障会清理临时文件并保留旧快照。替换后的父目录同步故障会让当前 store fail closed；用户重启后由快照重新判定状态。

## 取舍和后续边界

原子快照每次更新都会重写当前任务集合，适合 T003 的有限本地任务记录。随着历史记录规模或查询需求增长，后续任务可以提出 SQLite / journal 迁移，但必须保留 TaskId 和本机绑定、未知版本拒绝、单写者以及故障注入保证。T003 不触碰 CLI 身份语义，不实现网络、传输或 checkpoint bitmap，也不改变 storage/protocol。
