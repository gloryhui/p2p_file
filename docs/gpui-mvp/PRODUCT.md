# 产品规格与验收契约

规格版本 1.0。来源：本次用户确认。全文中的“必须”是任务验收条件；“初始决策”可由控制 Agent 在派工前带理由调整，涉及范围扩大须由用户确认。

## 1. 用户确认的目标

小巧、现代、原生 GPUI P2P 工具，用于自己的可信机器无人值守互传。
用户不用开终端或提前填写“允许接收的对端 ID”；接收端上线等待，发送端填写对方 ID 即可连接。
信令只用于发现/协商，不转发文件内容。不保证所有 NAT 都能直连，失败要真实反馈，不冒充连接成功。

| 能力 | 第一版契约 |
| --- | --- |
| 上线 | 首次填写信令 IP/主机及端口；保存配置后，每次启动自动注册及保活 |
| 身份 | 本机稳定完整节点 ID、复制按钮；重启不会变 ID；不展示私钥 |
| 连接 | 填对端 ID，握手并核对身份后显示“直连已建立” |
| 测速 | 默认单方向 30 秒；可选 1—10 分钟，步长 1 分钟；支持发送/接收方向选择 |
| 传输 | 选择本机文件（多选）或目录，展示任务进度和实时速度 |
| 并发 | 默认 1，用户可选 1/2/3 个同时发送的文件任务 |
| 带宽 | 等权、工作保持的近似公平调度；空闲份额自动让给可运行任务 |
| 暂停 | 双方均可暂停任务；进程保持运行；显式点击继续后恢复 |
| 中断 | 杀进程、断电、闪退、网络断开后保留任务和可验证的 durable 进度 |
| 恢复 | 重启不自动重新发送中断任务；用户点继续，连接可自动重建 |
| 目录 | 保留所选目录本身及内部相对结构，含空目录 |
| 重名 | 在最终发布前，将已有普通文件备份为“文件名+时间戳.后缀”，新文件占原名 |
| 接收 | 默认系统 Downloads；用户可改并持久化；不向对方暴露此路径 |
| 隐私 | 不提供列盘、列目录、任意路径读写接口；对方只拿到发送者显式选择的内容 |

授权边界：无“接收批准”不等于白名单已经存在。MVP 不阻止其它知道 ID 的节点尝试发送；设置页说明“可信设备 MVP：知道 ID 的节点可发送文件”。该说明不构成额外确认流程。

## 2. 第一版默认决策

以下用于让施工 Agent 无需反复猜测；控制 Agent 如更改，应更新文档和派工依据。

- Linux 首发测试发行版：Ubuntu 24.04 LTS x86_64；Wayland 和 X11 均列为测试项。不承诺所有 Linux 发行版。
- Windows 最低目标：Windows 10 22H2 x86_64；同时测试 Windows 11。
- macOS：仅 arm64，暂定 macOS 13+；T001 必须核查 GPUI 最低系统要求，若不支持此值，控制 Agent 记录最终要求；不得放弃 Apple Silicon。
- 最小窗口 760×560，初始约 960×680，支持高 DPI、缩放和键盘操作。
- 默认测速“本机 → 对端”30 秒；提供“对端 → 本机”。双向连续测试不是 MVP 必需项。
- 并发数作用于本机的发送队列，全局最多 3 个文件；接收端独立最多 3 个活动接收，不含小型控制流。目录作为 UI 分组，每个文件单独占槽。
- 允许多个 peer 保持连接。输入框选择当前发送对象；每个已建任务的 peer 固定，不随输入框变化。
- 切换接收目录仅影响新入队任务；未完成任务继续使用它建立时固定的接收根目录。
- 未完成任务保留，不自动清理 .part/.bitmap；不在 MVP 中新增“停止并删除数据”按钮。用户说的“停止”主要指异常进程终止。
- 修改信令配置触发明确的网络重配置状态；活动任务先进入可恢复状态，不静默换服务器。
- 对端离线的连接请求有界等待并显示状态；只重连信令，不无限自动重发失败文件。
- 目录中的符号链接、junction/reparse point、设备文件等第一版拒绝并列出原因，不追踪链接、不假装全部成功。
- 源文件变化导致内容身份变化时，旧任务报“源文件已变化”，用户重新添加；不得将新数据续到旧 bitmap。
- 不自动开机启动、不隐藏到托盘、不自动后台关闭窗口仍运行。正常退出保留未完成任务。

## 3. 界面结构

```text
┌ P2P File                                      设置 ┐
│ 信令：已连接 / 重连中 / 未配置                     │
│ 本机 ID  [完整 32 位十六进制 ID          ] [复制]   │
│ 对端 ID  [输入或粘贴                     ] [连接]   │
│ 对端状态：离线 / 连接中 / 已认证直连 / 失败原因     │
├ 文件传输 ─────────────────────────────────────────┤
│ [选择文件] [选择目录]          同时发送 [1 / 2 / 3] │
│ 名称/相对路径 方向 对端 进度 速度 状态 [暂停/继续] │
│ 目录可展开；任务列表可滚动；无任务时有清晰空态       │
├ 直连测速 ─────────────────────────────────────────┤
│ 方向 [发送/接收] 时长 [30秒/1…10分钟] [开始/取消]   │
│ 进度、瞬时 MiB/s、平均 Mbps、实际字节及实际耗时     │
└ 接收目录：本机路径 [选择]          简短错误/通知    ┘
```

设置页：信令主机/IP、端口、接收目录、保存；展示“仅可信设备无人值守模式”。
不把 NAT 诊断、开发术语、所有协议参数铺到主界面；连接失败详情可展开或复制。

## 4. 用户路径

### 4.1 首次启动与恢复启动

1. 创建/读取持久身份，显示完整 ID。
2. 没有信令配置：显示“先设置服务器”，不猜测公网服务器、不硬编码开发者私服。
3. 输入 host + port 并保存：先校验，再持久化，再连接。
4. 重启：加载同一身份、配置、任务；自动接入信令。
5. 未完成任务显示“已暂停”或“中断待继续”，即使连接成功也不自动继续。

### 4.2 连接

- 去除 ID 首尾空白；拒绝格式错误、长度错误及本机 ID。
- 信令在线和 P2P 在线分别显示。
- 只有 QUIC、身份握手、目标 ID 核对和桌面能力协商全部通过才启用业务。
- 错误显示具体阶段：服务器不可达、目标离线、直连失败、身份不符、版本不兼容。
- 重复点击不能创建无限连接；旧连接清理不能覆盖新连接状态。

### 4.3 文件与目录

- 文件选择：多个文件直接入队；目录选择：扫描出有界清单，保留顶层目录名及空目录。
- 取消系统文件选择器无副作用；扫描/哈希不能卡 UI。
- 新任务有稳定 ID 和固定 peer；UI 展示已校验写入进度，说明异常退出后可能回退到 durable 进度。
- 文件发送成功必须由接收端最终发布确认；写入 QUIC 或本地发送完成不能显示“完成”。
- 新传同名内容仍视为新任务，按重名规则处理；旧任务重试凭任务 ID 和持久化回执去重。
- 同一任务失败/继续不能制造重复备份；任务暂停后退出再开仍可继续。
- 目录任一子文件失败，分组不能显示整体成功；已完成子文件不重复发。
- 目录结构中“文件占着目录名”“目录占着文件名”要报冲突并暂停该任务，MVP 不递归改名已有目录。

### 4.4 暂停与中断

- 暂停有“正在暂停”中间状态：停止新调度、结束有界在途操作、保存恢复状态、双方确认。
- 接收端暂停不以 Abort/discard 实现，不删除数据。
- 没有收到暂停确认时显示“中断待继续”，不能声称已经完成安全暂停。
- 任一端杀进程后，存活端超时进入中断态；重新打开的端恢复记录，用户点击继续重新协商 bitmap。
- 接收端点击继续可请求对端恢复其持久任务；不得通过远端绝对路径请求任意文件。
- 对端源文件丢失/变化、任务不存在或拒绝继续，明确反馈，不永远等待。

### 4.5 测速

- 测速复用已认证直连连接，不读取文件、不生成 .part，不走文件 chunk 消息。
- 测速运行时默认禁止启动文件任务；已有传输时提示先暂停，不能静默暂停用户任务。
- 一条会话同时最多一个测速；对端也须仲裁，防止两边同时开始后抢同一单向流。
- 使用接收端统计作为结果依据，统一 MiB/s = bytes/sec / 2^20，Mbps = bytes/sec × 8 / 10^6。
- 取消、断线、超时不能显示成功；显示实际经过时间，不只显示配置时长。

## 5. 明确不做

接收批准/白名单产品流程、账户登录、云端存储、中继/TURN、远端目录浏览、同步盘、双向目录镜像、删除远端文件、自动更新、托盘/开机启动、移动端、Web 版、Intel Mac 打包。
不修改 #21/#22 来作为 GUI 完成的隐藏前提，不加入固定 1 GiB 队列，也不擅自调 Quinn window / congestion controller。

## 6. 产品验收清单

- [ ] 三平台真实 GPUI 窗口，支持中文输入、粘贴 ID、复制 ID、文件选择和高 DPI。
- [ ] A 上线不用填写 B ID；B 填 A ID 后双方能建立身份正确的连接。
- [ ] 同一身份重启不变，信令掉线重连、配置持久化正确。
- [ ] 两方向 30 秒及 1—10 分钟参数完整可用；至少原生长时边界有证据。
- [ ] 文件/目录含嵌套、空目录、中文和空文件均可发送。
- [ ] 文件实时速度、平均速度、进度、失败原因均真实。
- [ ] 默认 FIFO 单发，1/2/3 并发可切换、近似公平且无饿死。
- [ ] 双方可暂停/继续；任一端进程被杀后可手动恢复。
- [ ] 重名旧文件按时间戳保留；发布各崩溃点不丢旧文件、不假完成。
- [ ] 无列盘/列目录/任意远端路径读取能力。
- [ ] 原 CLI 测试与 E2E 仍通过；使用独立桌面能力版本处理兼容性。
