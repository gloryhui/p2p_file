# 分阶段施工任务卡

## 0. 执行规则

任务顺序 T001 → T012。每项必须由总控 Issue 的 DISPATCH 单独释放，施工 Agent 不自行领取“看起来可以做”的下一项。
T000 是本设计文档的初始审核，不是代码施工任务。初始控制流水号 GPUI-0000。
每次新派工（包括返工）使用新的递增流水号；task_id 可以保持不变，attempt 递增。
一个 PR 原则上只对应一张任务卡的一次施工，不将多个阶段塞入同一个大 PR。

文档中的模块是建议；当前 Issue 派工必须填具体文件范围、基线 SHA、文档 SHA、验收要求。
若任务过大，控制 Agent 可在开工前拆成 T00x-A/B 并提交任务卡修订；未发布新 DISPATCH 不自动生效。

### 通用交付 G

所有代码任务：
1. 最新 main 或控制单指定基线的独立分支，不直接改 main。
2. 有意义的测试覆盖新行为；保留原测试，不降低断言消除失败。
3. `cargo fmt --check`、`cargo test --all-targets`、`cargo clippy --all-targets -- -D warnings`。
4. 有 GUI 后，`cargo check --features gui --bin p2p-desktop`（若 T001 选 workspace，先把此文修订为实际命令）。
5. 改动传输/协议/网络/存储时：`cargo build` 后运行 `./scripts/e2e.sh`，避免测试旧二进制。
6. 相关三平台 CI；GUI feature 的构建/检查必须在 CI 显式开启，默认 core 测试不能替代。
7. 报告包含所有命令、退出结果、平台、日志链接、失败/未运行原因，不仅写“测试通过”。
8. PR、完整 head SHA、修改范围、回滚注意事项、风险；源代码中无 TODO 假装业务已完成。

仅文档任务可免 Rust 测试，报告必须明确“docs-only，未运行 Rust 测试”并检查 Markdown 链接和格式。
任何阶段没有真实依赖时使用可辨认的测试 fake；生产 UI 不可展示虚构连接/速度/成功状态。

## T000 — 文档准入与流水线初始化审核

负责人：控制 Agent。施工 Agent 此时只读等待。
输入：本套文档 PR、用户确认的产品范围、基线 312d466。
检查：文档内部引用、路径、任务前置依赖、无人值守边界、平台目标、pipeline 防重规则。
交付：文档 PR 合并，记录实际 merge SHA；然后发布 GPUI-0001 / T001，文档引用固定到合并后的 commit。
不通过：追加 CONTROL_HOLD，写明具体文档问题，人工或后续文档施工单处理。
不能把文档 PR 的通过当作 GUI 已交付。

## T001 — GPUI 技术验证、桌面壳和三平台构建

依赖：T000。
目标：先证明 GPUI 依赖、Rust 工具链、窗口及系统交互能在目标平台运行。
范围：Cargo、独立 desktop 入口、最小 ui 模块、CI、新增 ADR/开发环境文档；不动文件协议。
产物：
- 真实 GPUI 窗口，基本布局、中文文本、可编辑 ID 输入、剪贴板、文件/目录选择器示例。
- feature/workspace 隔离，CLI 默认构建不依赖 GUI 系统库。
- 依赖版本、最低系统/图形驱动要求、Linux 安装包清单。
- Linux/Windows/macOS arm64 编译 CI；原有 Windows 测试保留。
- ADR-001：GPUI/组件库选择，三平台可行性，构建命令和不确定项。

验收：
- G；无效输入/取消选择器不 crash；窗口大小/DPI 测试。
- Ubuntu 原生窗口截图与交互记录；Windows、Apple Silicon 有原生 smoke 测试计划和执行人/环境。
- Windows 10 必须做依赖最低版本核查；若 GPUI 实际最低 Windows 11，BLOCKED 并提交证据，不能擅自缩范围。
- 工具链/下载问题要单列环境阻塞，不用另一个 UI 框架替代 GPUI。
复核重点：不是静态截图或 WebView；组件版本互相兼容；没有悄悄开启重量级不需要的 webview 功能。
下一任务：T002。

## T002 — 平台配置、稳定身份与启动设置

依赖：T001。
范围：config、identity 适配、设置 UI、平台目录、单实例锁；不改变 CLI 身份语义。
产物：
- 系统配置目录与 Downloads 定位，首次配置 host/port，保存后自动发出上线意图。
- 稳定身份 ID 展示/复制；私钥安全保存；GUI 单数据目录单实例。
- 接收根目录、并发和测速参数配置。
- 清晰区分配置错误、目录权限错误和连接尚未建立。
验收：
- G；重启身份/配置相同；损坏配置不覆盖；无可用 Downloads 要求选择。
- IPv4/hostname/IPv6 地址输入与端口验证；连接实现尚未完成时显示“网络功能待接入”，不假在线。
- 不支持的本地路径编码显式报错。
- Windows Known Folder、Linux XDG、macOS 目录分别有测试或原生证据。
复核重点：不生成第二身份；不提交密钥；不将 host+port 错误拼接。
下一任务：T003。

## T003 — 持久任务模型、单写者存储与恢复状态机

依赖：T002。
范围：model/store、领域 API、任务列表基础事件。
产物：
- 固定任务 ID、peer、方向、源路径/接收根、manifest 身份、状态和错误。
- 新任务先持久化再开始；事务/原子快照；启动将活动任务转 Interrupted，Paused 保持。
- schema_version 和未知版本拒绝/迁移策略；单 writer 与锁。
- 发送/接收恢复接口，不依赖 UI 文本保存状态。
- ADR-002：SQLite 或原子日志的选择、fsync 语义及 Windows 原子更新策略。
验收：
- G；持久化中途注入失败不丢旧任务；损坏/截断数据库可诊断。
- 开启第二实例不共同写；重启仍有 peer/task/source/root。
- 任务 DB hint 不覆盖 durable bitmap；高频 progress 不每片 fsync DB。
复核重点：每次启动不能全部自动继续；TaskId 绑定 peer；没有远端绝对路径。
下一任务：T004。

## T004 — 长期在线会话、被动接入与多 peer 管理

依赖：T003。
范围：desktop/session、必要的 signal/net/transport/tunnel 重构、连接 UI 状态。
产物：
- 程序启动自动注册/心跳/退避重连。
- 接收端无需指定发送者；主动 lookup 与被动 offer 单事件循环路由。
- 正确 UDP 所有权、同 socket 映射、token 验证、认证与目标 ID 校验。
- 多 peer registry、generation、防重复连接、资源上限、退出清理。
- ADR-003：长期监听时新增 NAT 打洞请求的处理设计与测试。
验收：
- G；两实例 A 不填 B ID，B 查 A，双向认证成功。
- 主动查询不能吞掉其它 peer 被动 offer。
- 信令重启能重新注册；已有 P2P 可继续；重复点击、双方同时连不会注册互踢。
- 活跃连接存在时第三个节点仍能请求连接；旧任务/连接回调不能关闭新代连接。
- 同 socket 测试及真实双 NAT 待验证项，不伪造打洞已确认。
复核重点：不得删掉已有 TLS channel binding；不得多个 recv 竞争 UDP；不开放 GUI tunnel。
下一任务：T005。

## T005 — 桌面能力与任务协议

依赖：T004。
范围：desktop/protocol、必要 control message 扩展、编解码/分发/能力错误。
产物：
- 桌面 version/capabilities，连接按钮只有协商成功才显示业务可用。
- Offer/Resume/Pause/ResumeTask/Completed/Error 的任务绑定格式。
- 文件/目录相对路径、任务来源、回执标识；不传绝对路径。
- 单测速归属/互斥协商规则，为 T009 预留明确扩展点。
- 协议文档和 golden 编码测试；资源上限。
验收：
- G；旧 CLI 与 CLI 仍兼容；新桌面遇不支持 peer 明确失败。
- 重复、乱序、错 task_id、错误 peer、超大帧、非法路径、错误 manifest 均拒绝。
- 只追加不改旧 discriminant；若需不兼容版本变化必须记录并验证旧端拒绝。
复核重点：远端 Continue 只带已授权任务 ID，不能带任意源路径。
下一任务：T006。

## T006 — 单文件进度、双端暂停和崩溃续传

依赖：T005。
范围：transfer sender/receiver、desktop 任务适配、storage 最小 checkpoint API。
产物：
- 单文件真实收发 + 低频进度事件 + 最终回执。
- 双端 Pause/Pausing/Paused、Continue，断线转 Interrupted。
- 复用 durable checkpoint；暂停强制 checkpoint，重启重验 bitmap。
- 已完成任务 Complete 丢包后的幂等重试接口。
验收：
- G；双方暂停、同时暂停、暂停碰上最后一个 chunk、暂停超时。
- sender/receiver 任一进程硬杀后可继续；未 checkpoint 的 chunk 允许重传。
- 源文件变化/消失明确失败；不得复用旧内容 bitmap。
- receiver finalize 失败不能发 Complete；正常关闭不会删除未完成数据。
- 幂等回执必须覆盖“发布成功但发送端还不知道”窗口。
复核重点：不能用 download.discard() 做暂停；不能只保存 UI 百分比做恢复。
下一任务：T007。

## T007 — 目录清单、路径边界与重名事务发布

依赖：T006。
范围：files/publish、存储发布策略、目录协议适配、恢复 journal。
产物：
- 选择目录递归入队、保留顶层/子目录/空目录、受限扫描和取消。
- 路径跨平台验证，不跟随 symlink/reparse point。
- GUI 重名备份时间戳方案；CLI 原 no-overwrite 编号行为不变。
- 可恢复发布 journal、目标路径串行化、持久化回执。
验收：
- G；嵌套/空目录/中文/空文件；源链接、Windows ADS/设备名、UNC、穿越全部覆盖。
- 重名文件旧内容保留，新内容占原名；时间戳撞名不覆盖。
- 发布每个持久化边界前后注入故障并重开，验证不丢旧文件、不假完成、不重复备份。
- 两任务同目标竞争/外部进程抢占，no-replace 行为正确。
- Windows 被占用目标、磁盘满、权限错误保留可恢复状态。
复核重点：禁止用 exists()+rename 作为无竞态证明；不得把接收目录泄露给 sender。
下一任务：T008。

## T008 — 全局队列、1—3 并发与公平调度

依赖：T007。
范围：queue、任务生命周期集成、进度速率采样；不调 QUIC window。
产物：
- FIFO 默认串行；1/2/3 最大活动发送，接收资源上限独立生效。
- 等权按字节调度、可用份额借用、暂停释放槽、慢任务隔离。
- 目录任务分组与子文件独立槽、聚合进度和部分失败。
- 短窗口速率、累计确认进度、队列状态。
验收：
- G；可注入时钟和模拟写就绪验证公平、饥饿、借用，不依赖互联网带宽。
- N 个持续就绪任务的调度字节差在设计 quantum/在途上限内；报告算法及误差边界。
- 慢/离线 peer 不阻塞其它 peer；没有持有全局锁等待网络。
- 从 3 降 1 不杀活动任务且不继续超额补位；配置其它数值被拒绝。
- 每任务与总缓存上限测试；进度事件合并，终态不丢。
复核重点：公平证据不能只有“任务都最终完成”；不将三个 spawn 当等分带宽。
下一任务：T009。

## T009 — GUI 测速业务：30 秒到 10 分钟

依赖：T008。
范围：speedtest 有针对性扩展、desktop 互斥和测速控制；保留 CLI 默认行为。
产物：
- 30 秒、60—600 秒参数，两方向，低频速率事件、取消、完成数据。
- 每连接测试互斥，与文件活动互斥；不静默暂停用户任务。
- 600 秒的协议/超时/CLI 参数边界一致。
验收：
- G；两方向数据结果按 receiver elapsed；测试取消不污染下一次 accept_uni。
- 旧超时不在 300 秒错误结束；用可控时间测试边界，原生 600 秒验证记录到 T012。
- 无文件 I/O/manifest，接收目录无测试垃圾；无固定 Mbps CI 门槛。
- 双方同时点开始时有确定的接受/Busy 结果，不交叉消费数据流。
复核重点：测速数据走已认证同一 P2P 连接；不独立建一条未经身份确认的连接。
下一任务：T010。

## T010 — 完整 GPUI 产品界面与后台集成

依赖：T009。T001/T002 已有壳和设置，此阶段接入完整业务。
范围：ui、应用命令事件适配、少量界面所需领域查询接口。
产物：
- PRODUCT.md 布局：信令、完整 ID 复制、peer 输入/连接、传输队列、暂停/继续、并发、测速、接收目录。
- 文件/目录原生选择器，滚动任务列表，空态、错误态、重连态和恢复态。
- UI 不阻塞，中文 IME/粘贴/键盘/DPI；小窗口可用。
- 源/接收路径仅本机可见；测速与文件冲突操作有解释。
验收：
- G + GUI smoke；至少 Linux 真窗口截图或视频与操作步骤。
- UI 每个按钮有真实后端行为；无 placeholder 完成状态。
- 接收目录修改仅影响新任务；修改 peer 不重新绑定已有队列。
- 文件扫描/哈希/恢复期间窗口能移动输入；UI 无网络/文件阻塞操作。
- 收到新任务自动显示，不需要手动刷新；速度暂停后归零。
复核重点：不只审美验收，也检查 UI 显示与后端状态一致。
下一任务：T011。

## T011 — 端到端恢复、兼容与三平台故障回归

依赖：T010。
范围：专用测试 harness、故障注入、仅修复验收发现的范围内问题。
产物：
- 两实例和三实例自动化 harness；进程级强杀测试，完整性与目录结构比较。
- 新 scripts/desktop-e2e（实现形式按平台选择），输出可审计日志。
- tests matrix：目标/结果/平台/命令/commit SHA/证据链接。
验收矩阵：
| 场景 | 最少证明 |
| --- | --- |
| 未配置/配置恢复 | 无硬编码服务器、正确身份与目录 |
| 被动上线/多 peer | A 无预设对端、B/C 能接入 |
| 文件/目录 | 嵌套、空、中文、大文件、内容哈希一致 |
| 暂停 | sender/receiver/同时，继续无重复文件 |
| 强杀 | 任一端与发布边界，重启手动继续 |
| 重名 | 旧内容保留、新内容正确、回执去重 |
| 公平 | 1/2/3 并发、暂停/降并发/慢 peer |
| 失败 | 源变化、磁盘满、权限、网络断线、信令重启 |
| 安全边界 | 路径穿越、链接、非法帧、目标身份不符 |
| 兼容 | 原 CLI 测试与 E2E，桌面旧能力明确拒绝 |

复核重点：错误不能只写日志；不能用 graceful drop 测试替代 kill；不能删失败测试。

## T012 — 原生打包、真机验收和发布候选交付

依赖：T011。

产物：

最终动作：控制 Agent 完成 FINAL_ACCEPTANCE，列出全部合并 PR、发布候选、验证 SHA 和限制，然后关闭总控 Issue。

## 统一控制复核清单

- 派工/task/attempt/PR/head SHA 一致，实际 diff 在授权范围。
- 基线和文档 SHA 已固定，后续文档修改没有偷偷改变在建验收。
- 编译 CI 和测试对应当前 HEAD；CI pending 不合并。
- Critical/P0/P1 未解决不合并；中等问题是否阻塞按任务 DoD 写明。
- 无未说明的测试跳过、删测试、panic、无限重试、无界队列或敏感日志。
- 接口改变与下个任务依赖同步，main 在每次合并后可构建。
- 外部真机证据缺失明确标注，不能只凭施工报告自述通过。
