# ADR-003：T004 长期信令会话、peer 去重与 UDP 接收所有权

状态：T004 attempt 2 已通过 exact-head CI/实际复核，PR #32 已合并。以下为该阶段历史设计；T005–T011 任务/传输/队列/测速/UI/进程恢复已继续实现，见 ADR-004–010。T012 交付边界见 ADR-011。

## 决策

桌面启动在本机身份和已保存信令地址可用时创建一个长期 `DesktopSession`。它在独立 Tokio runtime 线程中拥有一条信令注册、一个 QUIC endpoint、一份 peer registry 和有界后台任务集合。UI 只通过有界命令与事件 channel 和会话交互；UI 不执行网络读写，也不持有可读取 UDP 包的句柄。

信令连接由现有 `SignalingClient` 完成 challenge-response 身份登记并启动心跳。桌面会话是 `next_event()` 的唯一调用者；它把 `PeerPending`、`PeerCandidates`、`Pong`、服务端错误和 reader 断开统一放进事件循环。主动 lookup 只写入发送队列，不等待或消费响应，因此其它 peer 的被动 offer 与 Pong 不会被某个 lookup 丢弃。掉线后按 1、2、4、8、16、30 秒的有界退避重连，并增加不超过 20% 的抖动；每次成功重连都用同一 `Identity` 重新登记。更改信令地址时增加配置 generation、取消旧 connect task 和 peer attempts，关闭旧连接，并忽略旧 generation 的迟到结果；显式配置变更与短暂信令掉线不同。重连只管理信令；已认证 QUIC 连接保留在 peer registry 中。

## 被动接入与多 peer

任何含有效候选和令牌的 `PeerCandidates` 都能建立 peer attempt；会话不要求本机 UI 预先选中对端。节点按 `NodeId` 维护最多 16 项的 registry，最多 8 个 pending/handshake attempt。每项带单调 generation；旧回调只有在 peer 与 generation 仍匹配时才能更新状态或移除连接。活动 peer 不重复增加认证任务；T011 后显式 Connect 会刷新信令映射，映射未变保留原认证连接，映射改变重新验证，见 ADR-010。候选等待在 15 秒后结束并可手动重试；终态不接受同代迟到结果。

同时连接时，较小的 `NodeId` 是唯一 QUIC initiator，较大的节点等待对方的 QUIC 入站。每个身份仅登记一次，多个 peer 共享 endpoint 和信令连接。连接状态只在 QUIC transport 建立、现有 Ed25519/channel-binding 握手成功且握手结果等于预期 `NodeId` 后标记 `Connected`。peer attempt、信令 connect、QUIC transport 和应用握手都具有超时或并发上限。

## UDP socket 与打洞包分发

DesktopNetwork 先绑定系统分配临时端口的唯一 UDP socket，并顺序使用该 socket 做 STUN 与候选准备。随后把同一个 socket fd 交给 Quinn 自定义 `AsyncUdpSocket` 适配器；端点与发送句柄共享底层 socket，但只有 Quinn 的 `poll_recv` 可以读取它。打洞任务只能通过 send-only `PunchSocketHandle` 发包，并通过 token 注册一个有界 channel 等待验证源地址，没有第二个 `recv` 循环。

适配器复用 Quinn 的 `UdpSocketState` 处理 ECN、GRO、GSO 与平台元数据。只有长度、magic、随机 128 位 token 均匹配当前活动注册的探测包才会从 QUIC 输入中过滤并送入对应 channel；其它包原样交给 Quinn，错误 token 或截断包不会产生 punch 进度。对 peer attempt 注册的有效探测包会记录实际 `recv` 源地址、目标 peer 和 generation。入站 QUIC 只可在该实际来源唯一对应当前活动 token 时进入对应 attempt；候选地址本身不会被当成已验证来源。来源数按 route 与全局上限约束，receiver drop 时解除注册并删除授权。

STUN 与 QUIC endpoint 由相同 socket 复用，信令重连不会重新绑定 UDP，也不会打断已认证 peer。当前没有 idle endpoint 重建路径；进程关闭用独立 watch 通道取消整个会话，不能被已满命令或 UI 队列阻塞。JoinSet 拥有 signaling-connect/accept/peer 任务；退出时取消，runtime 有界 shutdown，最后一个会话句柄有界等待并 join 网络线程。信令服务器也用 JoinSet 持有客户端 handler，handler 取消时 writer 由 abort guard 回收。T004 不新增转发或 `TunnelOpen` 能力。

## 清理与边界

session shutdown 或配置变化会取消旧信令连接并 fence 掉旧 generation。单 peer 错误只把同 generation 的 peer 状态置为失败/断开；不清除其它 peer。连接断开事件检查 registry generation 和连接 generation 后才移除条目。资源达到上限时返回明确诊断，不无限 spawn。

此设计只处理在线登记、直连认证和连接存活。没有实现 T005+ 能力协商、任务协议、文件/目录传输、测速、队列、通用隧道或中继。由于执行环境只有 Linux x86_64，Windows 与 Apple Silicon macOS 的证据只能来自对应 GitHub Actions；它们不是原生运行证据。

## 验证范围与未证明项

本地确定性验证通过真实 loopback TCP/UDP 与三个 session 实例覆盖被动 offer、共享身份登记、多 peer、第三 peer 在已有连接存活时推进、signal disconnect/restart 后同身份重登、generation fence 和 punch token/source 分发。现有 handshake 与 channel-binding 回归继续运行。

Loopback、单机或 CI 不能证明两个真实 NAT 间的映射、过滤行为和公网可达性。T004 不声明真实双 NAT 成功；应在 T011/T012 的两个独立网络环境中记录双方候选、实际 QUIC remote address、token 确认与认证结果。本 T004 历史记录没有原生窗口操作证据；后续 T010 已提供 Linux 原生窗口证据。物理 Windows、Apple Silicon、双 NAT 仍没有通过验收，不用后续 CI 代替。

## attempt 2 竞态修复与测试隔离

旧版完整并行套件复现为 316 PASS / 1 FAIL，第三 peer 测试等待认证超时；历史 attempt 1 也曾出现同时连接超时。审查发现两个路径问题：

- 首个探测可能在远端注册 token 前已被忽略。本端随后收到远端探测便退出发送循环，远端得不到回应。现在向通过 token 验证的实际源地址补发回应；确定性测试丢弃第一包后验证回应，不增大原有 timeout。
- 多候选环境中两端先收到的探测可能分别来自 LAN/loopback 等不同有效路径。入站 dispatcher 已以该实际来源的活动 token 绑定 peer/generation；再要求入站地址等于 responder 首次收到的探测地址会错误拒绝。保留 token/source 授权和预期 Ed25519 身份校验，去掉这一不成立的地址相等假设。

每测试独立临时 TCP/UDP 端口及身份，服务端停止后 join；session 最后句柄退出回收 runtime。没有全局串行测试或忽略失败测试。新增测试覆盖首次丢包、满 UI 队列退出、重复请求保留相同 connection、信令中断后的实际 QUIC 数据、离线截止时间及终态 fence、GRO 混合探测/QUIC 包和空 UDP 包、歧义 token 来源与 route 释放。适配器每次 poll 最多处理 32 批纯探测包，避免阻塞 QUIC 定时器；token 注册、来源和事件队列都有上限。

GitHub GPUI 三平台工作流运行完整 GUI library suite，不能只靠默认核心测试代替。实际检查次数、完整结果和 CI URL 记录在本任务证据文件及 Issue #24 REPORT 中；在全部完成前不将本 ADR 的设计描述当作验收通过。
