# 连接诊断（Issue #68）

主界面右上角「连接诊断」展开面板，再次点击收起。面板随现有任务观察循环更新，
不建立额外 Session、不启动测速或自动修改连接。可在主界面按建议重试或在设置中调整。

显示信令状态、本机实际创建的 IPv4/IPv6 UDP 路径、Relay 是否配置、对端候选数量、
当前已验证传输的 Direct/Relay 与实际地址族、设备身份/能力/访问授权阶段，以及发/收业务权限。
缺失起点、候选、地址族或路径时明确显示未知。信令在线、候选元数据和 Relay 分配均不提升业务权限；
传输路径事件只在已有核心通过当前世代的 authenticated transport 发布门槛后产生。

阶段耗时使用 GUI 收到事件时的本地单调时钟，是观察耗时，不是精确网络 RTT。
设备尝试从首次非终态阶段至首次会话连接或失败/断开停止，不把在线时长累计成连接耗时；
首次只收到已连接状态的连接起点未知。信令重试从新尝试开始重新计时，不包含之前的在线时长。
最近失败阶段取失败/断开之前观察到的阶段；未观察到明确阶段时显示未知，并给出固定排查建议。

诊断模型沿用 Session 外层 epoch 和 peer generation；旧 peer 事件不能覆盖新连接。
每次 Session 重建清空证据；最多保留 16 个连接、每连接最近 8 个阶段，终态旧连接优先淘汰，
淘汰世代的旧事件不能重新进入摘要。没有额外的无限原始日志缓存。

「复制脱敏摘要」和「导出新文件」生成同一份白名单文本，只输出固定阶段/建议、路径种类、
地址族、数量、观察耗时和摘要内部连接序号。密码、令牌、原始错误、IP、设备 ID/备注、
主机名、文件名和路径不进入模型或输出。这里不对任意原始日志做正则替换，因此不存在遗漏格式导致泄露的问题。

导出使用原生保存选择器，写入点击时的摘要快照，后台完成，不阻塞 GUI。只创建新文件，
既有文件不会被覆盖；取消不写入，失败显示提示。操作系统的剪贴板管理器可能保留已复制的脱敏文本。

自动验证覆盖：真实 IPv6 Direct 与 IPv4 Relay 的结构化路径事件、阶段/权限投影、
连接时间停止与重连计时、世代隔离/未知起点、敏感原始错误不进入摘要、有界阶段历史和导出不覆盖。
四个平台原生构建与 GUI 回归检查集成；对应平台原生保存选择器操作仍需人工验收。
